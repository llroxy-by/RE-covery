# G1 Joint Lab

本机网页控制台：http://127.0.0.1:8765

## 一键启动

```sh
./start.sh                              # 自动寻找机器人（推荐）
ROBOT_HOST=192.168.167.46 ./start.sh    # 指定地址，跳过自动发现
DRY=1 ./start.sh                        # 只做发现和指纹校验，不连
```

自动发现的做法：在每块已连线的 `en*` 网口上发一次 IPv6 链路本地广播，把邻居的 SSH 主机密钥指纹与本机固定的机器人指纹比对，**匹配才连**。这样机器人换了 IP（DHCP 变动）甚至只插了网线、没配 IPv4，都能找到它，也不会误连到同网段的其它机器。

网线直连时本机通常拿不到 IPv4（机器人那侧没有 DHCP），`en5` 会退到 `169.254.x` 自动地址。这时不需要改任何网络设置 —— 用 IPv6 链路本地地址 `fe80::…%en5` 直连即可，脚本会自动处理。

脚本按序做四件事：发现并校验机器人 → 建立 SSH 主连接（密码只在终端输一次）→ 启动控制台 → 打开浏览器。找不到机器人时会列出扫到的候选及各自指纹，说明为什么跳过。

控制台与机器人断线后会自动重连（每 2 秒检查一次 SSH 主连接），不需要重启 `server.py`。

## 手动启动

在终端建立 SSH 主连接（密码仅在 SSH 提示中输入）：

```sh
ssh -M -S /tmp/kitt-console-live.sock -o ControlPersist=no -N galbot@192.168.167.46
# 走网线、没有 IPv4 时用链路本地地址（网口名按 ifconfig 里的实际值）：
# ssh -M -S /tmp/kitt-console-live.sock -o ControlPersist=no -N 'galbot@fe80::69c8:289b:61e:26f4%en5'
```

另一终端运行：

```sh
python3 server.py
```

控制台只监听本机回环地址。Python 桥接程序通过 SSH 在机器人内存中运行，无文件上传、SDK 安装或系统配置修改。使用当前机器已核实的 `/data/galbot/lib` 作为进程环境。

功能：真实关节位置和速度、左右臂/头部分组、自定义角度单关节点动、0.01–0.05 rad/s 限速、机器人校准 URDF 关节限位校验、软件轨迹停止、ESC、记录导出。无状态、过期状态和非法参数禁止运动。浏览器心跳丢失时请求停止；SSH 断开时桥接看门狗请求停止。软件停止不替代实体急停，网络或 SDK 阻塞可能导致停止无法及时执行。

真机 SDK 1.10.0 已恢复返回 16 个关节的实时状态。已取消人为测试角度上限，使用本机校准 URDF 的 lower/upper 限位，未进行大角度运动验证。

参考：https://developer.galbot.com/docs/SDK/1.10.0/g1/zh/api_python_reference
使用 `set_joint_positions(..., is_blocking=False, speed_rad_s=..., timeout_s=5)` 与 `stop_trajectory_execution()`。命令成功仅表示已接收，不表示关节已到位。没有碰撞规划功能；每次动作都需现场观察。

## 底盘转身
按住左转/右转，松开停止。速度 0.01–0.30 rad/s，默认 0.05。使用 set_base_velocity 的单次发送模式，机器人内存桥接以 10Hz 续发；0.6 秒没有收到新的按住续租请求时调用 stop_base。普通状态轮询不能续租底盘。失焦、指针取消、ESC、取消安全勾选均发送停止。乱序旧指令被拒绝。软件停止无法保证网络或 SDK 故障下及时制动，实体急停须保持可用。未自动执行真机转身测试。

## 动作预设
点头采用官方 head_joint2 俯仰示例，默认偏移 5° 后返回起点。腕部挥手在当前手臂姿态下令 joint7 往复，不会自动抬臂。举手采用示教：手动调好所选手臂后保存其 7 个关节位置，预设按关节依次恢复到该姿态。示教存在本机浏览器 localStorage 中，换浏览器或机器人后需重新示教。

选择预设只显示目标角度；确认动作空间后点击执行。所有关键帧预先检查模型限位；按实时反馈等待到位再继续。停止、失焦或反馈失效会中止序列。没有碰撞检测，不能把任意起点到示教姿态的路径称为已验证。新增预设只做了软件测试，尚未进行真机运动验证。

### 自动识别举手目标（更新）
动作预设已移除手动保存与 localStorage 示教读取。当前会话内，手腕高于肩部 8cm、全部关节反馈有效且稳定至少 1.2 秒/3 次采样时，自动记录该手臂第一个识别到的抬臂姿态。主动控制期间不采集；反馈中断会重置待识别窗口。未识别到目标时，举手预设不会执行。识别是姿态分类，不等于路径碰撞校验，也不会自动生成从未观测过的举手目标。

关节与动作预设速度上限已调整为 0.20 rad/s（约 11.5°/s），默认仍为 0.02 rad/s。底盘速度独立设置。未执行提速后的真机动作。

## 交替摆手活动信号

默认关闭，网页勾选现场确认后手动开启。基于当前校准 URDF 计算双臂肘关节 ±2° 候选，仅选择手腕向上且位移不超过 3cm 的候选；姿态不适用时拒绝启动。以 0.03 rad/s 执行左抬/左回/右抬/右回循环，每个关键帧使用实时反馈确认到位。循环采用固定起点，避免累积偏移；发现其他关节偏离起点超过 2°、状态过期或执行超时就中止。

循环期间本页的其他运动控件禁用。关闭开关、ESC、失焦、页面隐藏或连接失效会中断循环并请求停止；停止不会自动回位。网络/SDK 故障可能阻止及时制动，须保留现场看护和实体急停。此模式用于可见活动演示，不是安全心跳、设备健康证明或无人看管模式。尚未自动执行真机循环测试。

交替摆手参数已更新为肘关节单次偏移 20°、速度 0.20 rad/s。取消旧 3cm 位移约束，网页显示模型预测位移，仍保留关节限位及反馈校验。当前共享内存再次占满，真机计划尚未验证，循环保持关闭。

## 全关节控制（SDK 1.10）

关节位置控制从 SDK `get_joint_names(True, [group])` 主动关节清单发现，只有同时存在模型限位及新鲜反馈的关节才可操作。当前 G1：头部2、左臂7、右臂7、腿部5，共21个。每个关节可单独选择、输入角度和速度；实际限位由校准模型读取，不硬编码设备角度。腿部动作会影响躯干高度及重心，新增功能未进行真机运动测试。

底盘4关节提供只读位置/速度，不允许通过位置接口驱动；转向使用底盘 API。双夹爪通过专用开口/速度/夹持接口操作。未安装的灵巧手不显示为可控制设备。
