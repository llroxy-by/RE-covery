# 遮挡记忆演示 · 手机摄像头自主识别版

> 一句话：**手机当相机，系统自动识别并框住整块积木；拿盒子挡住后，它保留原位置并判断能否盲抓，全程不需要点选目标。**
>
> 演示代码：`rebench/tools/occlusion_live.py`
> 判据代码：`rebench/occlusion.py`（世界模型 / 抓取走廊 / 决策）
> 真机接入：`docs/OCCLUSION_MEMORY.md`
> 自动测试：`rebench/tests_occlusion_live.py`

## 1. 怎么跑

```bash
python -m rebench.tools.occlusion_live --port 8302
```

手机与电脑连接同一局域网，打开终端打印的 HTTPS 地址：

```text
https://<电脑IP>:8302  →「高级」→「继续前往」→ 允许摄像头
```

和 `vision/tools/phone_live.py` 使用同一套证书与取流方式。程序会自动识别主分支的 `vision/` 与功能分支的 `vision-rescue/vision/` 两种源码布局，默认配置路径也会随之一同切换。若只要验证空桌差分、不用调色板：

```bash
python -m rebench.tools.occlusion_live --port 8302 --no-color
```

## 2. 无人工点选的四步演示

| 步骤 | 现场动作 | 系统自动完成的事 |
|---|---|---|
| ① 学空桌 | 打开页面，前约 1 秒保持桌面空着、手机不动 | 累计 12 帧并取逐像素中值，得到空桌基线 |
| ② 放积木 | 把一块或多块积木放到画面里 | 自动检测、**框住整块物体**、分配 ID、反投影并记住位置 |
| ③ 放盒子 | 用盒子挡住其中一块积木 | 目标框变黄色虚线 `MEMORY`；状态切到「被判遮挡」；记忆位置不变；给出盲抓或拒绝决策 |
| ④ 拿开盒子 | 恢复原来的无遮挡画面 | 自动重新识别同一目标，事件显示「记忆校验：位置一致」 |

不需要字母标签，不需要登记模板，也不需要点击 `/lock`。页面唯一按钮是「重新学习空桌」，用于清空全部状态后重演，不属于目标识别步骤。

## 3. 自主检测与整块外接框

系统有两条互补的检测来源：

1. **颜色检测**：调用现有 `vision.detector.Detector`，使用 `vision/config/desktop.json` 的调色板。识别结果带稳定 ID，例如 `block_red_01`；框来自完整颜色轮廓的外接矩形，不是 72×72 模板小框。
2. **空桌前景差分**：当前灰度图与空桌基线做差分，经去噪和 25×25 闭运算把高光、阴影、贴纸碎片连回整体，再取完整连通域外接矩形。任意颜色的物体都能检测，ID 为 `obj_1`、`obj_2`……；后续用整块外观模板在原位置附近跟踪。

两路结果按 IoU 合并，避免同一物体重复建框。新前景若覆盖已有目标，会被解释为**障碍物区域**，不会新建一个 `obj_n`；因此拿开盒子后不会留下“幽灵物体”。

## 4. 页面字段

| 字段 | 含义 |
|---|---|
| 来源 | `颜色检测` 或 `新出现的前景` |
| 框 `(x,y,w×h)` | 最后一次看见时的**整块物体外接框**；遮挡时保留该框作记忆提示 |
| 记忆位置 `(base_link)` | 最后一次真正看见目标时的三维位置，遮挡期间绝不更新 |
| 这条记忆多久了 | 距最后一次看见的秒数；默认 ≤30 s 为新鲜，>300 s 为过期 |
| 位置不确定度 | 按 `2 mm/s × 时长` 增长，封顶 36 mm |
| ① 有历史位置 / ② 区域被占 / ③ 记忆未过期 | 三条证据全部成立才判 `occluded` |
| 决策 | `可以盲抓` / `拒绝抓取` / `先重看一眼`，附走廊原因与手腕角度 |

## 5. “遮挡”与“真被拿走”怎么区分

真机可用视线和深度作证；手机没有深度，因此同时使用**目标外观**和**空桌基线**：

| 观测量 | 阈值 | 解释 |
|---|---|---|
| 前景目标模板相关系数 | < 0.50 | 原来的目标本体已匹配不到 |
| 当前区域与目标上次外观的平均灰度差 | ≥12 | 区域内容已变化 |
| 当前区域与空桌基线的平均灰度差 | ≤6 | 区域已恢复为空桌，目标是**真被拿走** → `missing` |
| 区域非空且外观已变化 | 上述两条共同满足 | 被其他物体占据 → `occluded` |
| 检测漏帧但区域外观基本没变 | 不满足遮挡证据 | 按不可安全抓取处理，不贸然盲抓 |

这里必须比较两次。只比较“当前空桌”和“上次积木”会得到很大的差异，若因此判遮挡，就会对空位置盲抓。当前实现已用空桌基线修复这个问题，并有两种检测模式的自动测试兜底。

## 6. 为什么有时能盲抓，有时必须拒绝

演示页直接调用 `check_vertical_approach()` 与 `pick_strategy()`，不是按“有没有盒子”写死结果。平行二指有朝向：开合方向需要约 10 cm 半走廊，垂直方向只需约 3.3 cm；前方近盒子可以通过手腕转 90° 获得净空。

同一组合成目标、只改变盒子底边位置的实测结果：

| 盒子位置 | 合成图底边 y | 走廊结果 | 决策 |
|---|---:|---|---|
| 挡在前方较远 | 680 px | `clear` | `blind_pick` |
| 挡在前方较近 | 520 px | `tight_clearance`，手腕 90° | `blind_pick` |
| 扣在目标正上方 | 420 px | `corridor_blocked`，0/45/90° 均被挡 | `refuse` |

关键不是盒子在图里有多大，而是它的**桌面接触线**是否落入目标正上方的抓取走廊。规划器没有碰撞检测，所以正上方被占时不能放宽判据。

## 7. 四个容易写错的实现点

### 7.1 框必须来自完整轮廓

框是检测轮廓的 `boundingRect`，前景遮罩先闭运算再取外轮廓。用于跟踪的模板也裁自整块框，但模板尺寸不会反过来限制显示框。

### 7.2 障碍物不能拿目标自己的 bbox 代替

目标框必然覆盖目标，若把它当障碍物，所有朝向都会与抓取走廊相交，决策便恒为拒绝。当前实现用“目标最后可见时的整帧”与当前帧差分，取覆盖目标中心的最大变化连通域作为障碍物。

### 7.3 单目必须用底边接触线，不用整块 bbox 推位置

“挡在前面”和“压在正上方”在图像中可能高度相似，但桌面接触线不同。障碍物仅用底边上 10% 与 90% 两个点反投影；进深无法由单目宽度可靠推出，演示中按 5 cm 薄板估计。

### 7.4 记忆必须允许被推翻

只有目标重新可见时才调用 `world.see()` 更新位置；遮挡时只读记忆。与此同时，空桌证据会把目标改为 `missing`，避免机器人永远相信一段已经失效的历史。

## 8. 验证记录

新增 `rebench/tests_occlusion_live.py`，全部使用合成帧，不需要手机或摄像头：

- 颜色检测框覆盖完整红色、绿色物体，而非固定小模板；
- 纯前景模式自动建立两个稳定 ID，遮挡一个不改变另一个，且不生成幽灵物体；
- 遮挡后恢复，位置与遮挡前一致；
- 前方远、前方近、正上方三种盒子分别得到 `clear`、`tight_clearance`、`corridor_blocked`；
- 颜色与纯前景两种模式下，直接拿走目标都判 `missing`，决策表为空、障碍物为 0。

本次完整回归结果：

```text
python -m unittest vision.tests.test_vision

python -m unittest rebench.tests_perception rebench.tests_occlusion rebench.tests_occlusion_live

```

修复后的 8302 服务另做了 HTTPS 端到端验证：`GET /` 返回 200；连续提交空桌、积木、遮挡、恢复四种图像后，接口依次返回两个整块目标框、仅红色目标 `occluded` 且 `blind_pick/clear`、两目标恢复 `visible`，并产生「记忆校验：位置一致」事件。

## 9. 几何限制

手机没有深度。位置由像素反投影到桌面平面得到，相机使用演示用固定位姿：

```text
相机位置 (0.30, 0.0, 1.05)，注视点 (0.72, 0.0, 0.71)，桌面 z = 0.71
内参：fx 657.4  fy 656.9  cx 636.4  cy 356.1
```

屏幕坐标只能用于演示“记忆没有变化”，不能直接作为真机标定结果。真机应通过 `SdkBackend.observe_world()` 提供真实三维位姿与障碍物盒，接入方法见 `docs/OCCLUSION_MEMORY.md` §5。

## 10. 排障

| 现象 | 首查 |
|---|---|
| 手机打不开页面 | 是否同一局域网；必须使用 HTTPS；自签证书需点「继续前往」 |
| 一直不识别新物体 | 前 12 帧是否真是空桌；手机是否移动；点击「重新学习空桌」后重试 |
| 框碎成多个 | 目标与桌面反差是否足够；现场可优先用调色板覆盖的积木 |
| 挡住后仍显示可见 | 盒子是否真正遮住完整目标，而非只盖住一角 |
| 拿走目标却显示遮挡 | 检查桌面光照是否较空桌基线发生明显变化；重新学空桌 |
| 决策拒绝 | 查看 `corridor`：正上方被占是正确拒绝；前方盒子则检查接触线是否被误检到目标位置 |
| 改动代码后行为没变 | 重启 8302 服务；已经运行的 Python 进程不会自动加载新代码 |
