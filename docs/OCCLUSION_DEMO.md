# 遮挡记忆演示 · 手机摄像头版

> 一句话：**手机当相机，点一下积木 → 拿盒子挡住 → 它还记得那块积木在哪，并给出"能不能下手抓"的判断。**
>
> 代码：`rebench/tools/occlusion_live.py`（约 600 行，含手机页面）
> 判据：`rebench/occlusion.py`（世界模型 / 走廊可行性 / 决策）
> 真机接入：`docs/OCCLUSION_MEMORY.md`

## 1. 怎么跑

```bash
python -m rebench.tools.occlusion_live --port 8302
```

手机打开终端打印的地址（同局域网，HTTPS，自签证书）：

```
https://<电脑IP>:8302   →  「高级」→「继续前往」→ 允许摄像头
```

和 `vision/tools/phone_live.py`（8300）用的是同一套证书与取流方式，所以现场流程一致；
两个页面互不干扰，可以同时开。

## 2. 三步演示

| 步骤 | 动作 | 页面反应 |
|---|---|---|
| ① | **点一下画面里的积木** | 绿框锁住，卡片出现「记忆位置 (x, y)」「记忆 0 s」 |
| ② | 拿盒子**挡在手机与积木之间** | 绿框变**黄色虚线框**（`MEMORY`）；状态切「被判遮挡」；位置数字**一个都没变**，只有"记忆多久了"在走表；底部给出决策 |
| ③ | 把盒子拿开 | 绿框回来；事件里出现「重新出现，记忆校验：位置一致」 |

**不用写字母、不用登记、不依赖颜色阈值** —— 现场随便拿一块积木都能演。
身份来自"你点的是哪一个"，跟随用模板匹配。

## 3. 页面字段

| 字段 | 含义 |
|---|---|
| 记忆位置 (base_link) | 最后一次**看见**它时的三维位置，遮挡期间不更新 |
| 这条记忆多久了 | 距最后一次看见的秒数。≤30 s 视为新鲜，>300 s 视为过期 |
| 位置不确定度 | `2 mm/s × 时长`，封顶 36 mm（按实测深度噪声 12 mm 的 3 倍） |
| 当前帧 | 看见时是模板匹配相关系数；看不见时是"那片区域的灰度变化量" |
| ① 有历史位置 / ② 区域被占 / ③ 记忆未过期 | 判遮挡的三条证据，必须全中才算 `occluded` |
| 决策 | `可以盲抓` / `拒绝抓取` / `先重看一眼` + 理由 |

## 4. 判据怎么落到 2D

真机链路里三条证据是"有历史位置 / 视线被挡或深度说遮 / 未过期"。手机没有深度，
第二条换成**画面证据**：那片区域灰度和"上次看见时"差了多少。

| 量 | 阈值 | 含义 |
|---|---|---|
| 模板相关系数 | < 0.42 | 目标本体看不见了 |
| 区域灰度平均绝对差 | ≥ 12 | 那块地方被**别的东西**占了 → `occluded` |
| 同上 | < 6 | 那块地方变回空桌面 → 东西是**真被拿走**的 → `missing` |

第三条很关键：**记忆必须允许被推翻**。不留这个出口，机器人会对着一块早被人拿走的积木
反复盲抓、反复夹空。

## 5. 决策为什么会切换

`blind_pick` 与 `refuse` 都是真实几何算出来的，用同一张照片 + 合成盒子实测：

| 盒子放法 | 障碍物底边 | 走廊判定 | 决策 |
|---|---|---|---|
| 挡在前方约 20 cm | x≈0.67 m | `clear` | `blind_pick` |
| 挡在前方约 10 cm | x≈0.77 m | `tight_clearance` | `blind_pick`（贴着，但能过） |
| **扣在积木正上方** | 与目标同位 | `corridor_blocked` | **`refuse`** |

原因：平行二指张开 12 cm，垂直走廊按 ±10.3 cm 算。盒子挡在前方、不压在上方，
垂直下降撞不到；压在正上方就必须拒绝——规划器坏了、没有碰撞检测，这条不能松。

## 6. 实现要点（三个非显然的地方）

### 6.1 点选锁定，而不是识别身份

`cv2.matchTemplate`（`TM_CCOEFF_NORMED`）+ 只在上一位置 ±150 px 内搜索，
画面缩到 0.5 倍再匹配（每帧几毫秒）。好处：

- 不依赖标签、不依赖颜色阈值、不必现场登记；
- 现场换任何积木都能演；
- 相关系数天然给出"还看得见吗"这个量，不用另造指标。

代价：大幅度移动或旋转会跟丢。演示时手机保持不动即可。

### 6.2 障碍物范围必须**观测**，不能拿目标自己的框代替

这是最容易写错、也最致命的一处。第一版用"目标 bbox 外扩 25%"当障碍物，
结果**永远**判"走廊被占"——因为它必然盖住目标，系统就变成"什么都不敢抓"。

正确做法：拿"上次看见时的整帧"和当前帧做差分，取**盖住目标的最大变化连通域**，
那才是挡上来的那个东西的轮廓。

### 6.3 用底边（接触线）反投影，不用整块 bbox

单目图像里"盒子挡在前面"和"盒子压在正上方"投影几乎一样。用整块 bbox 反投影，
两种情况都会盖住目标，判据就没有分辨力。

而物体与桌面的**接触线**（图中物体的底边）才是它真正的落脚位置：

- 挡在前面的盒子 → 接触线投影在目标之前 → 占位不覆盖目标 → 允许盲抓；
- 压在正上方的盒子 → 接触线就在目标自己的位置 → 覆盖 → 拒绝。

目标的落点同样用**底边中点**，不用框中心（标签/贴纸贴在正面，框中心会系统性偏几厘米）。

## 7. 踩过的坑

| 现象 | 根因 | 处理 |
|---|---|---|
| 放一个盒子，画面里**所有**目标一起消失 | 深色矩形让画面边框凑出一个 1280×706 的"标签"（面积占比 7.5% < `max_area_ratio` 10%、长宽比 1.8、内部又亮，全部过关），`_dedupe` 把真标签当成"被它包含"全吞掉 | `find_labels` 加闸门：占画面一半以上的框不是标签（**这条对 8300 生产页同样有效**） |
| 决策永远是"拒绝抓取" | 拿目标自己的 bbox 当障碍物 | 改为差分观测障碍物范围（§6.2） |
| 宽盒子被判成"很深、挡手" | 用宽度推厚度 | 单目看不出厚度，按薄板 5 cm 保守估 |

## 9. 几何限制（务必写清楚，别当成标定）

手机没有深度。位置由像素反投影到桌面平面得到，相机位姿是**演示用的固定假设值**：

```
相机位置 (0.30, 0.0, 1.05)，注视点 (0.72, 0.0, 0.71)，桌面 z = 0.71
内参用任务书里 D405 的实测值：fx 657.4  fy 656.9  cx 636.4  cy 356.1
```

所以屏幕上的 `(0.95, -0.11)` 只能用来演示"记忆没有变"，**不能当标定结果**，
更不能直接喂给机械臂。真机上把 `SdkBackend.observe_world()` 补上（约 40 行，
见 `docs/OCCLUSION_MEMORY.md` §5），就换成真实三维。

障碍物进深也只能按薄板估 —— 这也是文档里反复强调"三维一定要用腕部深度"的原因之一。

## 10. 排障

| 现象 | 首查 |
|---|---|
| 手机打不开页面 | 是否同一局域网；必须 https；证书警告要点「继续前往」 |
| 点了没反应 | 先要有一帧画面（`/frame` 已通），`last_clean` 为空时 `/lock` 会返回"还没有画面" |
| 目标很快跟丢 | 手机不要大幅移动；画面里目标不要小于 72 px |
| 挡住后一直显示"看得见" | 盒子没真正盖住目标（模板还能匹配上一部分）——把盒子往目标正前方推近一点 |
| 挡住后判"按丢失处理" | 区域灰度变化 < 6：说明那里变成了空桌面，是真被拿走，不是被挡 |
| 决策总是"拒绝抓取" | 盒子压在目标正上方（此时本就该拒绝）；或走廊确实被占 |
