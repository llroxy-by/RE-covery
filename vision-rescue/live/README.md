# live — 实时读数（重写版）

    ./start.command            # 或： ../.venv-vision/bin/python -m live.server
    浏览器自动打开 http://127.0.0.1:8400/

## 为什么重写

旧版把「标注后的整幅 JPEG」base64 回传，浏览器再 `img.src = data:...` 解码。
画面帧率 = 检测帧率，一条链上任何环节慢一点，画面就跟着卡，实测被钉在 2.6fps。
本地算法本身只要 20-30ms，全耗在"把图片送回去"上了。

现在：

| | 旧版 | 现在 |
|---|---|---|
| 画面 | 服务端回传标注图 | `<video>` 直接放本地流，30fps 原生 |
| 每帧数据 | ~100KB base64 JPEG | ~0.9KB JSON |
| 帧率 | 2.6fps（被 380ms 定时器卡住） | 画面 30fps / 检测 18fps |
| 标注 | 画在服务端图里 | 浏览器 canvas，60fps 重绘、框做缓动 |
| 慢帧 | 排队积压 | 单槽位、最新帧优先，直接丢过期帧 |

## 三个文件

- `core.py` — 找白标签 → 读字母 → 跨帧稳定 → 和基准比。不碰 HTTP、不画图。
- `server.py` — 一个检测槽位 + 几个 JSON 接口（`/detect /anchor /compare /enroll /forget /snapshot /zones`）。
- `page.py` — 页面本身。渲染全部在浏览器本地完成。

## 识别的取舍（实测出来的，不是设想）

- **只显示真读出来的字母**。现场是展会/黑客松：灯带、屏幕、条幅到处都是，
  一张照片能框出 20+ 个"像标签的方块"。旧版把这些都画成物体，屏幕上像
  "认出一堆"，其实全是噪音。现在候选框只进 `candidates` 字段（页面勾选
  「候选框」才显示），画面上只会出现真的字。
- **模板库负责近景，模型只负责兜底**。库里有字母时，模型不再逐个候选
  去框读 —— 实测它会把条幅、屏幕上的字读成 K/E/J/D/A，凭空多出积木。
  只有"一块都没读到"时，才把**通过形状检查、且位于画面中央**的那一块
  喂给模型（正是人手举积木、标签只有 40×45px 的场景）。没有像标签的东西
  就什么都不读 —— 镜头对着人脸时，绝不能凭空读出一个字母。
- **字母要连读两帧才显示**（模型读的三帧），避免单帧读错时闪一下。
- 基准比较**只看位移**（默认 90px）。分区 A/B/C/D 是给人看的参考框，
  那套坐标是按另一台机器画的，拿它当判据会把没动报成被挪动。

## 精度闸门（"把眼睛和凳子认成 A"就是这个治的）

四道全过才算一块积木，任何一道不过就只进 debug 列表：

| 闸门 | 量什么 | 默认 | 挡掉什么 |
|---|---|---|---|
| 白度 | 标签比四周亮几倍 | ≥ 1.12 | 眼睛（白眼球+瞳孔，四周是脸，比值≈1.0）、白墙、屏幕 |
| 笔画粗细 | 最粗笔画 / 短边 | ≤ 0.30 | 瞳孔、纯色块、椅子扶手这种实心团 |
| 填充率 | 四边形面积 / 外接框 | ≥ 0.50 | 一条边、一条缝、乱七八糟的轮廓 |
| 分数差 | 第一名 − 第二名 | ≥ 0.06 且 ≥ 0.70 | "跟谁都不像也不都不像"的桌面花纹 |

实测（同一批样本）：

- 近景 A/B：0.87 / 0.97，第一名甩开第二名 0.41 / 0.46 → 全部通过
- 缩到 40% 的远景：0.87 / 0.87 → 仍然通过
- 展会广角照：8 个候选，白度 0.92-1.18、分数 0.30-0.54 → 全部 reject
- 合成的"眼睛"：分数 0.50-0.54 → reject
- 顺带更快：被闸门挡掉的候选不再进模板比对，单帧 18-25ms

阈值可以直接改 `vision/config/mac.json` 的 `label.precision`，不用动代码。
误报多 → 调高 `contrast_min` / `margin_min`；漏读多 → 调低它们。
页面「候选框」开关会把每个候选的**拒绝原因**写在框上（不够白 1.02 / 笔画太粗 0.42 / 分低 0.61 …），
照着手调最快。

## 自动严格，手动可用

连续检测的原则是**宁可不认，也不能乱认** —— 屏幕上多出一个不存在的积木，
比少读一块严重得多。但总有"人举着积木离机位一米、标签只有 40×45px"的情况，
任何自动判据都不可靠。

所以分成两条路：

- 自动：四道闸门全过才显示，没过就当没看见。
- 手动：点「读画面中央」，把正中 60% 交给模型，等 4-15 秒给一个答案。
  读错了用户自己一眼能看出来，这是**用户主动要的**，不算误报。
  第二次点同一个画面是秒回（结果按感知哈希缓存）。
