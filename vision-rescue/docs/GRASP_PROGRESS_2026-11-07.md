# 抓取续接记录（本次实测）

设备：galbot-echo，G1 2.2 / A22 双臂，SDK 1.10.0。通过现有 SSH 连接读取；执行器经标准输入在内存运行，没有上传文件、部署 SDK 或修改机器人系统。

## 已修复

- `lowprobe_grasp.py` 默认和 `--dry` 仅读取当前视角，不开爪、不移动手臂或底盘。运动需显式 `--execute`，并已先做当前状态碰撞检查。
- 不再通过 SCP 上传后忽略上传失败，改为有超时、按请求 ID 匹配的内存传输。
- 路径预演返回一次性 `plan_id`；执行保存的同一组关节角，不重新求 IK。计划 15 秒过期，任一已采样关节组变化超过 0.5° 会拒绝；碰撞检查结束后再查一次。
- SDK 返回失败时即使带有解也拒绝；关节采样使用完整状态，指尖高度使用每个采样点的实际方向。
- 执行前检查显式完整状态的采样碰撞结果；失败、碰撞、反馈缺失或到位误差超限即停止，不自动重试运动。
- 移除“够不着就自动前移底盘”和失败后自动抬臂的行为。夹爪读数不再被直接宣称为抓取成功。
- 预览的 GET 升降接口返回 405，不能因打开链接触发运动。
- 相机内参读取失败时停止三维定位，不套用历史值。

## 续接：绿色积木已实际夹起

用户明确选绿色并确认摆好后，重新取图；画面一度有手遮挡，机器人保持静止，直到新图确认手已离开。

另修正头部图像模型：SDK 返回 `distortion_model=plumb_bob`、D 全零、`roi.do_rectify=True`。物理镜头类型虽为 fisheye，交付图像不能再次按等距鱼眼换算。绿色目标用针孔模型反投影约 `(0.7236, 0.1141)` m，对应深度峰约 `(0.7253, 0.1173)` m；旧鱼眼公式的 x 约 0.662 m，偏差约 6 cm。已新增 camera_ray 并替换 overview 的错误换算；新增两项回归测试，现共 13 项通过。

抓取全过程每一步使用新预演的一次性解，执行前完整状态碰撞检查成功，执行反馈误差均小于 1 mm。最终修正目标至 `(0.731, 0.114)` m，腕部先到 z=0.940，再到 z=0.918；合爪只下发一次：目标宽度 0.010 m，速度 0.03 m/s，effort=3，非阻塞后等待 4 秒。读回宽度 0.0240 m，静止。图像确认绿色积木在两指之间，未继续下探。

随后保持夹持，腕部低速垂直从 0.918 抬至 0.968 m（5 cm），到位误差 0.60 mm。两次反馈宽度 0.0240 / 0.0239 m、静止；抬升后图像确认绿色积木随夹爪升起，橙色积木仍在桌上。实际抓取成功。
