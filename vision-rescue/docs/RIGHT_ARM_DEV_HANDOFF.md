## 交付目标

扩展现有执行框架，使其能明确选择左/右臂；已有调用不指定 arm 时仍使用左臂。右臂最终实测和双臂并行由队长收到交接后完成，这次只交付代码与离线证据。

优先处理：
1. 梳理执行器中左臂硬编码，引入统一的 arm 配置/解析，非法 arm 必须拒绝。左右臂分别绑定 joint_group、gripper、工具安装帧、所需传感器；具体 SDK 标识须查适用于 G1 SDK 1.10.0 的官方资料或现有库定义，不能靠字符串替换猜测。未确认的能力明确拒绝执行。
2. 状态、FK/IK、一次性计划与执行、夹爪反馈和本机会话支持 arm 参数。计划绑定 arm，不能右臂拿左臂的 plan_id 执行，不能跨臂重用工具参数。
3. 预演与碰撞检查继续使用完整机器人状态，包含另一条手臂、头、腿；不能退化为只检查当前臂。维持原有超时、漂移、一次性解、失败停止和初始化/释放逻辑。
4. 右臂工具几何未独立确认，禁止把左臂的估计值直接作为已验证右臂标定。需要每臂独立配置与验证状态；缺失标定可只读/离线预演，但运动执行必须拒绝。不得默认自动标定，更不能通过降低桌面高度使检查通过。
5. 提供一个右臂离线示例和回归测试。此阶段不实现同时下发两条手臂的真实运动，不将单臂路径分别通过碰撞检查当作双臂同时运动安全证明。

## 必须保留的执行约束

- motion 必须显式开启；开发任务全程关闭。
- SDK 返回失败或 TIMEOUT 就停止后续运动。允许只读诊断，但不能因“还在朝目标动”就当成功继续；不能自动重发未知结果的运动。
- 抓取、抬升、运输或下降失败后，不得继续松爪。
- 使用测量桌面，不反推/伪造桌面高度；不能降低安全阈值来补偿未知工具长度。
- 保留反馈新鲜度检查；effort 阈值或夹爪开口单独不证明持物成功。
- 不用镜像左臂坐标或机械限位来假设右臂可达。
- 不添加任何启动即运动、导入模块即连接机器人、测试失败自动真机兜底的行为。
- 本任务不需识图，不调用视觉服务、不调用 GPT 看现场图像，不读取或复制密钥。

## 离线验收清单

用假 SDK/假传输完成，测试不得访问机器人网络：
- 未指定 arm 的旧左臂调用兼容；right 正确路由；非法值拒绝。
- 左右臂工具帧、关节组、夹爪反馈独立，不串数据。
- 计划记录 arm，跨臂 plan_id、过期、重放和姿态漂移拒绝。
- 碰撞采样包含另一只手臂；碰撞/FAULT/TIMEOUT 后不继续执行。
- 缺失右臂标定拒绝运动；只读路径不调用运动 API。
- 任意一次运动失败不会触发后续夹爪释放。
- 现有23项离线回归继续通过；若为合理接口改动调整测试，说明原因，不删掉断言来过关。
- 用 Python 3.8 语法兼容方式编写机器人执行器，本机工具按现有 Python 3.9 环境兼容。
