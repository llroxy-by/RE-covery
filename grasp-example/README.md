## 审阅结论
1. detect_object 读取左腕 RGB/深度，但 object_pose_camera 是固定值，没有实际目标检测。
2. pick_and_place 忽略感知位置，使用 GRASP_POSE_BASE_PLACEHOLDER。
3. pose_camera_to_base 仅转换位置，输出姿态固定为单位四元数；不能直接作为任意物品的抓取姿态。
4. 启动会先移动腿、头及双臂到固定初始姿态；后续还会导航与放置，并非仅夹取。
5. 缺少 numpy/opencv 时源码会调用 pip install；现场接入应移除自动安装，复用已有依赖或项目专用环境。
6. 初始化失败后源码仍继续；夹爪返回值未用于阻止后续动作，感知异常会返回零位姿。这些均需在部署前改为失败立即退出。
7. 当前相机观察台提供头部左相机 JPEG；本例使用左腕 RGB-D，两者不能直接替换。现有字母识别结果也不等于经过标定的三维抓取位姿。

## 现场接入顺序
由现场技术人员确认指定开发目录和已有 SDK 环境；不要运行 SDK 安装器、替换共享库或启动服务。
先完成只读左腕 RGB-D、相机内参、坐标变换检查；接入真实检测，生成带时间戳、坐标系及夹爪 TCP 姿态的目标。
随后移除所有占位回退值、默认初始全身动作及不需要的导航/放置；补齐初始化、夹爪状态、到位与失败停止检查。
现场确认物体尺寸、夹爪宽度、接近方向、工作空间和碰撞环境后，分阶段验证预抓取、接近、夹取、抬升。
当前没有这些标定与实测证据，不能把本示例称作可直接抓起现场物品的成品。
